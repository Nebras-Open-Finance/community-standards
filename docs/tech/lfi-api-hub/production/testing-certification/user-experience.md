# LFI CX Certification – User Experience Evidence Requirements

## Overview

The **Customer Experience (CX) Certification** ensures that all Licensed Financial Institution (LFI) customer-facing journeys (web and mobile) comply with the UAE Open Finance CX standards.

It validates that consent, authentication, and consent management journeys are intuitive, transparent, and consistent across all use cases.

---

## 1. Purpose

The CX Certification ensures:

- Consent journeys are intuitive and compliant  
- Authentication & authorization flows are user-friendly  
- Consent dashboards provide transparency and control  
- UX screens meet mandatory CX standards  

---

## 2. Scope

### Supported Channels
- Web applications  
- Mobile applications  

### Coverage Rules

CX certification must be submitted separately for:

- Each brand  
- Each customer segment (Retail / SME / Corporate)  
- Each interface type (Web vs Mobile)  
- Each use case  

---

## 3. User Experience Evidence Submission

LFIs must submit a **CX certification evidence package**.

---

### 3.1 Application Metadata

Each submission must include:

- Completed CX certification request template  
- Brand name  
- Customer segment  
- Platform (Web / Mobile)  
- Relevant use cases  

---

### 3.2 Screen Evidence (Mandatory)

For each use case, the following screens must be submitted:

#### A. Consent Journey Screens
- Consent initiation screen (TPP redirect context)
- Authentication / login screen
- Consent approval screen
- Consent confirmation screen  

#### B. Consent Dashboard Screens
- Active consents list
- Consent details view
- Consent revocation flow (if applicable)

#### C. Supporting Screens (where applicable)
- Error states (login failure, invalid consent, etc.)
- Timeout / retry flows
- Edge case handling screens  

---

### 3.3 Screen Requirements

All submitted screens must:

- Be in **English**
- Reflect **Pre-Production or Production**
- Match production exactly if pre-production is used
- Represent actual user experience without mock simplifications

---

## 4. CX Compliance Requirements

Submitted screens are assessed against the following principles:

---

### 4.1 Informed Decision-Making
- Clear explanation of consent purpose  
- Transparent permissions  
- No ambiguity in user actions  

---

### 4.2 Simple & Frictionless Journey
- Minimal steps for authentication and consent  
- No unnecessary navigation  
- Seamless redirection between TPP and LFI  

---

### 4.3 Parity of Experience
- UX must be equal or better than direct banking channels  
- No additional friction in TPP-initiated journeys  

---

### 4.4 Trust & Familiarity
- Authentication must use LFI credentials only  
- Clear indication of bank identity  
- Consistent branding and familiar UX patterns  

---

### 4.5 Transparency & Control
Users must clearly understand:

- What data is shared  
- Who it is shared with (TPP identity)  
- Duration of consent  

Users must also be able to:
- View active consents  
- Revoke consent easily  

---

### 4.6 Vulnerable User Protection
- Accessible UX design  
- Clear language and readable flows  
- Avoid misleading or complex steps  

---

## 5. Certification Process

### Workflow

1. LFI prepares CX evidence package  
2. Submits per:
   - brand  
   - segment  
   - platform  
3. Nebras reviews submission  
4. If issues are found → resubmission required  
5. If compliant → CX Certification is issued  

---

## 6. Validation Authority

- **Certification Body:** Nebras Open Finance  
- Review Focus:
  - UX compliance at screen level  
  - Journey completeness  
  - Alignment with CX standards  

---

## 7. Outcome

Once approved:

- CX Certification is issued to the LFI  
- Required for exit from Pre-Production  
- Mandatory before production go-live  

---

## 8. Summary

CX Certification ensures all LFI consent and account access journeys are:

- Simple  
- Transparent  
- Secure  
- Standards-compliant  

Validated through structured UX screen evidence submitted to Nebras.
